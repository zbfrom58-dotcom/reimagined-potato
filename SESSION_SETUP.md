# Авторизация 16 аккаунтов на Railway

`userbot.py` больше **не вызывает `client.start()`** для авторизации. Это важно для Railway: хостинг не может ответить на интерактивный запрос Telethon `Please enter your phone`.

Для каждого аккаунта в Railway Variables должны быть заранее заданы:

- `<ACCOUNT>_API_ID`
- `<ACCOUNT>_API_HASH`
- `<ACCOUNT>_SESSION` — готовая **авторизованная Telethon StringSession**

Пример для `DR_WOOD`:

```text
DR_WOOD_API_ID=12345678
DR_WOOD_API_HASH=...
DR_WOOD_SESSION=1BVtsOH...
```

## Как получить SESSION

Сделай это **локально на своём компьютере**, а не на Railway. Используй существующий `generate_session.py`, если он есть в твоём исходном проекте, либо отдельный генератор StringSession для Telethon. После успешного входа скопируй полученную строку в соответствующую Railway Variable.

Не добавляй SESSION в GitHub и не публикуй её: это секрет авторизации аккаунта.

## Что будет при незаполненной SESSION

Приложение не будет падать. В админке аккаунт получит статус `🟠 нужна авторизация`, а в логах не появится запрос номера телефона. После добавления SESSION достаточно перезапустить сервис и запустить аккаунт из админки.
